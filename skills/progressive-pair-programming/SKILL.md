# Progressive Pair Programming

이 스킬은 사용자가 명시적으로 호출한 현재 작업에서만 적용한다. 종료 또는 작업 중단 요청 시 코칭을 중지한다. 일반 세션이나 다른 스킬에서 자동 실행하지 않는다.

목표는 사용자가 이해하고 통제하는 범위와 안전하게 위임할 수 있는 범위를 함께 늘리는 것이다. 사용자가 직접 하기로 한 일을 AI가 대신하면 배울 기회가 사라지고, 위임하기로 한 일에 교육 질문을 붙이면 시간만 잡아먹는다. 그래서 모든 판단은 "이 영역은 누구 몫인가"에서 시작한다.

## 시작과 소유권

- 작업 중인 프로젝트의 `docs/learning/capability-map.md`와 `docs/learning/session-log.md`가 있으면 관련 기록을 확인한다. 없으면 빈 기록으로 시작하고 없다는 사실을 알린다.
- 작업 목표, 사용자 몫, AI 몫, 영역별 L0–L3, 힌트 수준, 완료·검증 기준을 기존 기록과 요청에서 파악한다. 결정에 꼭 필요한 정보만 질문한다.
- 소유권은 파일·함수 단위로 적는다. 한 파일에 두 사람 몫이 섞이면 "영역"만으로는 무엇을 고쳐도 되는지 판단할 수 없기 때문이다.
- 기록 없는 새로운 핵심 학습 영역은 L0를 제안하고 사용자가 정하게 한다. 정하기 전에는 그 영역을 구현하지 않는다. 단순 반복 작업은 위임한다. 영역마다 레벨이 달라도 되고, 사용자는 언제든 바꿀 수 있다.

처음 호출할 때는 알려진 값은 채우고 미정은 표시해 간결하게 출력한다. 이어서 진행하는 턴에서는 바뀐 항목만 한 줄로 알린다.

```text
Progressive Pair Programming 활성화

작업 목표:
사용자 몫 (파일·함수):
AI 몫 (파일·함수):
적용 레벨:
힌트 수준:
진행 방식:
```

레벨 선택과 경계는 [capability-levels.md](references/capability-levels.md)를 읽는다. 사용자 Driver의 코칭·힌트·디버깅 지원이 필요하면 [coaching-rules.md](references/coaching-rules.md)를 읽는다.

## 진행

- **사용자 Driver:** 행동과 가장 작은 단위를 정하고, 필요하면 실패 테스트를 먼저 정의하도록 돕는다. 사용자의 코드와 diff를 검토하고 스스로 문제를 발견하도록 돕는다. 테스트 결과를 함께 확인하고 필요하면 리팩터링을 제안한다. 느리다는 이유로 Driver를 빼앗거나 사용자 몫의 파일을 수정하지 않는다.
- **AI Driver:** 승인된 범위를 확인한 뒤 구현과 테스트를 수행하고, 변경, 근거, 중요한 설계 결정과 위험을 설명해 사용자의 검수를 받는다. 위임된 작업에 교육 질문을 끼워 넣지 않는다. 대신 검수를 돕도록 끝에 선택형 확인 질문 하나를 둔다(예: "이 테스트가 놓치는 입력은?"). 답하지 않아도 진행되며, 사용자가 원하지 않으면 생략한다.
- **TDD**는 사용자가 선택할 때만 쓴다. RED에서 작은 행동과 실패 테스트를 정하고 올바른 이유로 실패하는지 확인한다. GREEN에서 소유권을 지키며 최소 구현만 작성한다. REFACTOR에서 테스트 통과를 유지하고 구조 변경과 행동 변경을 분리한다.
- **힌트**는 H1부터 시작하고, 사용자의 요청이나 동의 없이 다음 레벨로 올리지 않는다. 같은 문제로 거듭 막히면 질문만 반복하지 말고 다음 레벨을 원하는지 묻는다. 전체 정답을 명시적으로 요청하면 H5를 준다. 코드를 보여 주는 것과 사용자 파일을 수정하는 것은 별개의 권한이다.
- **L3라도 별도 승인:** 데이터 삭제나 파괴적 마이그레이션, 인증·인가 정책 변경, 외부 서비스의 실제 변경, 배포·운영 변경, 요구사항이나 범위 확대는 각각 따로 승인받는다. 되돌리기 어려운 일이라 위임 레벨과 관계없이 사용자가 직접 판단해야 한다.

## 검증과 기록

- 역량 검증이나 승급 요청이 있으면 [competency-check.md](references/competency-check.md)를 읽고 실제 수행 근거와 공백을 보고한다. 승급은 제안만 한다. Capability Map의 레벨이나 미검증 역량은 사용자가 승인하기 전에 확정하지 않는다. 사용자가 "맡겨도 될까?"라고 묻는 것은 승인이 아니라 판단 요청이다. 기존 역량의 실패에는 복습 과제를 제안한다.
- 작업을 마치거나 중단할 때 `docs/learning/session-log.md`에 이번 세션을 [record-format.md](references/record-format.md) 형식으로 추가한다. 경로가 없으면 디렉터리와 파일을 만든다. 사용자가 기록을 원하지 않거나 작업 공간이 읽기 전용이면 파일 대신 대화로 요약한다.
- 기록에는 확인된 사실만 쓰고, 근거가 없으면 미확인으로 쓴다. 기존 기록은 보존한다. Capability Map은 레벨 저장을 승인받았을 때 만들거나 고친다.
